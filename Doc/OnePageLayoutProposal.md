# 1 ページ固定レイアウト実装案

## 1. 概要

現在の UI はページ全体が縦に伸び、ブラウザ全体のスクロールで各エリアへ到達する構成になっている。
これを、`Navigator` / `Map Canvas` / `Workspace` を常時 1 画面内に収めるデスクトップ向けレイアウトへ変更する。

同時に、ヘッダーを簡素化して縦方向の占有を減らし、中央のマップ表示領域を優先する。

## 2. ゴール / 非ゴール

### ゴール

- デスクトップ幅ではページ全体を 1 画面固定にし、ブラウザ全体の縦スクロールを無効化する
- 左右ペインを独立スクロール化し、ホイール操作がそのペイン内だけで完結するようにする
- 中央の `Map Canvas` を残り高さへフィットさせ、常に作業領域を最優先にする
- Canvas 上のホイール操作はページスクロールではなくズームとして扱う
- ヘッダーを詰めて、初期表示の fold 内にマップ本体が見える状態を強化する

### 非ゴール

- 初回でモバイルとデスクトップに完全に同じレイアウト挙動を適用すること
- 左右ペインの内容整理や機能再配置まで同時に大きく見直すこと
- Canvas の描画ロジックやマップデータ構造そのものを変更すること

## 3. 前提・仮定

- この変更はデスクトップ利用を主対象にする
- モバイルや狭い横幅では、必要に応じて現行に近い縦積みへフォールバックしてよい
- 既存の `MapCanvas` ホイールズーム実装は維持し、ページ全体スクロールを止めることで競合を減らす
- 左右ペインの「マウスオーバーで独自スクロール」は、専用 JS よりも `overflow-y-auto` による標準挙動を優先する

## 4. 現状整理

### 現行挙動

- ページ全体が `min-h-screen` ベースで縦に伸びる
- ヘッダーがカード的に大きく、縦方向の余白も多い
- 左右ペインは本文量に応じて伸び、結果としてブラウザ全体スクロールが必要になる
- 中央 Canvas もその流れの中にあるため、画面サイズによっては初期表示で視認しづらい

### 関連モジュール

- `src/App.tsx`
  ページ全体の 3 カラム構成、ヘッダー、各ペインの親コンテナを持つ
- `src/components/ShellPanel.tsx`
  左右ペインのラッパーで、スクロール責務を持たせる候補
- `src/components/MapCanvas.tsx`
  Canvas 本体。現在もホイールズームを持つため、1 ページ固定と相性がよい

### 既存制約

- `Map Canvas` は高さが十分に取れないと操作性が落ちる
- 左右ペインのセクション数が多いため、スクロール領域の `min-h-0` と `overflow-y-auto` を正しく入れないと高さ計算が破綻しやすい
- モバイルまで同じ固定レイアウトにすると、可読性より窮屈さが勝つ可能性が高い

## 5. 提案アーキテクチャ

### コンポーネント構成

- ルートを `100dvh` 基準の固定レイアウトへ変更する
- ヘッダーは 1 段へ圧縮し、装飾カード感を弱める
- 本文は `Navigator | Canvas | Workspace` の 3 カラムを `minmax(0, 1fr)` を含む grid で固定する
- 左右ペイン内部だけを `overflow-y-auto` にし、中央は `overflow-hidden` の作業領域にする

### データフロー / シーケンス

1. ページルートは `overflow-hidden` にする
2. ヘッダー高さを縮小し、残り高を本文へ渡す
3. 本文 grid は `min-h-0` を維持し、各カラムが親高さを超えないようにする
4. 左右ペインはホイール時にそのペインのみスクロールする
5. 中央 Canvas は残り高いっぱいを使用し、ホイールは既存どおり zoom へ流す

### 既存パターンへの整合

- 状態管理や Canvas 操作ロジックは変えず、主にレイアウト責務のみを `App.tsx` と `ShellPanel.tsx` に寄せる
- `MapCanvas.tsx` はホイールズームを継続し、ページ全体スクロール無効化の恩恵を受ける

## 6. インターフェース設計

### UI レイアウト I/F

- ルート
  - `min-h-screen` から `h-[100dvh]` へ変更
  - `overflow-hidden` を付与
- ヘッダー
  - 説明文を短縮
  - ステータス表示を 1 行へ圧縮
  - 重いカード装飾を減らす
- 本文
  - `grid` 親に `min-h-0` を付与
  - 中央カラムは `minmax(0, 1fr)` を維持

### スクロール / 入力 I/F

- 左右ペイン
  - `overflow-y-auto`
  - `overscroll-behavior: contain`
- 中央 Canvas
  - 親は `overflow-hidden`
  - `wheel` はズーム専用

### 例外・バリデーション

- 狭い幅では 3 カラム固定をやめ、現行に近い縦積みまたは 1 カラムフォールバックへ切り替える
- 高さ計算が崩れた場合に備え、主要コンテナへ `min-h-0` を明示する

## 7. 実装手順

### Step 1

- `App.tsx` のルートを `100dvh` 固定へ変更する
- ヘッダーを簡素化し、縦余白とカード装飾を減らす

### Step 2

- 本文 grid を `min-h-0` 前提の 3 カラム固定に変更する
- 中央の Canvas 領域が常に残り高さを使うように整理する

### Step 3

- `ShellPanel.tsx` へ独立スクロール責務を追加する
- 左右ペインに `overflow-y-auto` と `overscroll-behavior` を入れる

### Step 4

- デスクトップでの wheel 挙動を確認し、左右ペインはスクロール、中央は zoom になることを確認する
- 狭幅時のフォールバック崩れを手動で確認する

## 8. 非機能要件チェック

### 性能

- レイアウト変更が中心で、描画負荷への影響は軽微
- 高さ固定により再レイアウトは増えるが、現在の構成では支配的コストにはなりにくい

### セキュリティ

- セキュリティ影響なし

### 可観測性

- Console エラーの増減を確認する
- 特に `ResizeObserver` と wheel 周りで新規警告が出ないことを確認する

### 互換性

- `100dvh` の採用でモバイル系ブラウザ挙動は変わりうる
- 初回はデスクトップ優先とし、必要なら狭幅だけ `min-h-screen` ベースに戻す分岐を入れる

### 運用

- UI セクション追加時は左右ペインのスクロール量が増えるため、主要操作は上部に寄せる方針を維持する

## 9. リスクと緩和策

- Risk: 高さ固定後に `min-h-0` 不足で中央 Canvas やペインが縮まない
- Mitigation: 親 grid、中央セクション、左右ペインの各段で `min-h-0` を明示する

- Risk: モバイルで 1 ページ固定が窮屈になり操作不能に近づく
- Mitigation: 初回からブレークポイントで縦積みフォールバックを残す

- Risk: ヘッダーを削りすぎて状態把握がしづらくなる
- Mitigation: 重要なステータスだけを残し、詳細は右ペインへ寄せる

## 10. 影響範囲

- `src/App.tsx`
  全体レイアウト、ヘッダー圧縮、本文 grid の変更
- `src/components/ShellPanel.tsx`
  独立スクロールと高さ制御の責務追加
- `src/components/MapCanvas.tsx`
  既存ホイールズームとの整合確認。必要なら親コンテナの高さ追従だけ調整
- `Doc/`
  実装判断用の提案文書を追加

## 11. Definition of Done

- デスクトップ幅でブラウザ全体の縦スクロールが発生しない
- 左 `Navigator` と右 `Workspace` がそれぞれ独立スクロールする
- 中央 `Map Canvas` が常時 1 画面内に収まり、ホイールでズームできる
- ヘッダーの縦占有が減り、初期表示からマップ作業に入れる
- 狭い画面幅で完全破綻しない
